# 观澜桌面壳 · 设计

**日期**:2026-07-27
**状态**:设计已确认,待实现计划
**触发**:「现在我想做一个桌面端应用 点击能启动 不要依托于浏览器了」

---

## 1. 目标与非目标

**目标**:双击一个图标,出现一个独立的观澜窗口——没有地址栏、没有标签页、任务栏里是它自己的图标——而且它**自己负责确保后端活着**。

**非目标(明确排除)**:

| 不做 | 为什么 |
| --- | --- |
| 原生控件重写界面 | 会推翻现有全部前端,违反「UI 只填充不重建」。壳装的就是现有页面。 |
| 打包成可分发 exe | 需要连同 FastAPI 后端、`engine/`、`G:/stocks` 数据一起解决,是数量级更大的工程。本设计只服务这台机器。 |
| 壳接管服务器生命周期 | 关窗口不停服务器。见 §4。 |
| 开机自启 | 「点击能启动」是手动语义。YAGNI。 |

## 2. 已确认的决策

| # | 决策 | 选择 |
| --- | --- | --- |
| D1 | 做多大 | **壳 + 保姆**:独立窗口 + 自己检查/拉起 9999 |
| D2 | 关窗口后 9999 怎么办 | **继续跑**。看门狗仍是唯一业主,壳不与它争所有权 |
| D3 | 多窗口 | **现在就做**。Ctrl+点 / 中键点顶栏开新窗 |
| D4 | 技术选型 | **pywebview + WebView2** |

**D4 的机器实测依据**(2026-07-27):WebView2 Runtime `150.0.4078.99` 已装;`pywebview` 干净解析出 5 个纯 wheel(`pywebview 6.2.1` 本体 + 4 个传递依赖 `pythonnet 3.1.0`、`clr_loader 0.3.1`、`bottle 0.13.4`、`proxy_tools 0.1.0`),无需编译。Node v24.14 在(Electron 可行但要把 Node 工具链重新引回零 Node 依赖的仓库);Rust 不在(Tauri 需先装)。

Edge `--app` 方案被 D1 与 D3 直接排除:它没有 JS 桥,做不了多窗口,而且窗口开出去之后服务器挂了仍然白屏——正是本设计要解决的场景。

## 3. 模块边界

新增包 `guanlan_v2/desktop/`:

| 模块 | 唯一职责 | 依赖 |
| --- | --- | --- |
| `supervisor.py` | 「9999 活着吗?能不能让它活?」**完全不碰 GUI** | 仅 stdlib |
| `bridge.py` | 暴露给网页的 JS API(开窗、查状态) | 无——窗口工厂靠注入 |
| `shell.py` | pywebview 接线:建窗、注入标记、挂桥、心跳 | pywebview |
| `boot.html` | 引导 / 错误 / 掉线状态页 | 静态 |
| `__main__.py` | 入口 | `supervisor` + `shell` |

`supervisor` 与 `bridge` 都不 import pywebview;GUI 能力一律以**可调用对象注入**。全部真实逻辑因此都能无窗口跑测试。

**现有文件只动一个**:`ui/_shared/guanlan-nav.js` 增加一段条件分支(§5)。

### 3.1 supervisor 的红线

`supervisor` **只会启动看门狗代际;永远不杀任何进程、不碰端口**。看门狗(`scripts/check_9999.ps1`)仍是 9999 的唯一业主,壳只是又一个「发现它死了就拉一把」的触发源——与 `guanlan_v2/server.py` 里 `_checker_revive_loop` 的互拉逻辑同构。

派生方式沿用看门狗派生继任的同一条命令行(WMI `Win32_Process.Create` + `conhost --headless`),原因见 [[watchdog-9999]] 大坑①②:本机 Task Scheduler 派生的进程会冻死,会话后代会被回收。

## 4. 启动序列

**窗口立刻出现**,不等服务器。冷启动可能几十秒,先黑屏最难受。窗口先装 `boot.html`,状态实时更新,健康后再导航。

```
建窗 → 显示 boot.html
  ├ 探活 9999 ─────── 通 → 导航到 /ui/console/观澜 · 帷幄.html
  └ 不通 → WMI 拉起 check_9999.ps1 一代
            └ 每 2s 轮询,上限 90s
                 ├ 通   → 导航
                 ├ 超时 → 「看门狗已拉起,90s 内仍未监听」+ [重试] [看日志尾部]
                 └ 派生失败 → 显示 WMI 返回码
```

探活端点 `GET http://127.0.0.1:9999/workflow/list`,与看门狗用的是同一个,超时 5s。默认落地页为帷幄——`guanlan-nav.js` 里它标着 `home: true`。

`boot.html` 是**新界面**,现有产品页里没有对应物,因此不与「UI 只填充不重建」冲突;它不替代任何现有页面。配色取自 `ui/_shared/tokens.css`,以免看着像外人。用户已在设计评审中明确接受这一点。

### 4.1 从 2026-07-19~07-26 那次 7.5 天停机继承的两条硬规矩

1. **壳派生看门狗时必须从环境里剔除 `GUANLAN_PORT`。** 那次停机的根因就是这个变量漏进代际链、被一路继承,导致每一代拉起的 server 都去 bind 9998,9999 永远没有监听。壳是一个新的派生点,不能再开同样的口子。
2. **启动形态必须是 `pythonw -m guanlan_v2.desktop`(快捷方式「起始位置」= 仓根),不是跑脚本文件。** 2026-07-26 晚 9999 起不来正是脚本形态下 `sys.path[0]` 是包目录、仓根不在路径上所致(见 `tests/test_server_script_launch.py`)。`__main__.py` 自己再做一遍仓根引导兜底。

## 5. 多窗口

`guanlan-nav.js` 增加一段,**只在桌面壳里生效**:

| 操作 | 行为 |
| --- | --- |
| 左键点 | 当前窗口跳转(现有行为,一行不改) |
| Ctrl+点 / 中键点 | 壳开新窗口 |

三个必须处理的细节:

- **中键要监听 `auxclick`**:`click` 在现代浏览器里中键不触发。两个事件都挂。
- **`window.pywebview` 可能尚未注入**(pywebview 在 `pywebviewready` 事件前不可用)。桥不在时**不调用 `preventDefault`**,直接退回普通跳转——降级,不是报错。
- 浏览器里 `window.GL_DESKTOP` 为 undefined,整段分支跳过,**行为逐字节不变**。

现有的 `?embed=1` 提前 return(帷幄右栏 iframe 嵌入卫生)保持在最前,不受影响。

新窗口同样注入 `GL_DESKTOP` 与桥,因此可以继续开窗。默认尺寸 1400×900,层叠偏移以免完全重合;标题取页面 `<title>`。

### 5.1 open_window 的安全闸

`bridge.open_window(url)` 只接受 **origin 恰为 `http://127.0.0.1:9999` 且路径以 `/ui/` 开头**的 URL;其余(`file://`、外部主机、其他端口、`/api` 类路径)一律拒绝,并返回带类型的拒绝理由供顶栏显示。

理由:页面里渲染着 RSS 快讯与 LLM 输出,这些内容我们不完全控制;原生壳里一个不设限的开窗 API 是真实的提权面。

## 6. 掉线降级

**心跳是进程级的一条,不是每窗口一条。** 整个壳进程每 10s 探活一次 9999;**连败 3 次**(即约 30s)判定掉线,向**当时打开的每一个窗口**推一层浮层:「与 9999 的连接中断」+ [重试] [看日志]。用浮层而非换页,DOM 得以保留,恢复后自动撤掉全部浮层。三个窗口不会变成三倍探活流量。

**硬约束:一次掉线只拉一次看门狗——按壳进程计,不按窗口计。** 开着三个窗口时掉线,仍然只派生一次。看门狗自己有 30s 周期;壳再叠一层重试会变成派生风暴——与 07-20 那个「重启 → 撞端口 → 死 → 重启」的循环是同一个形状。恢复健康后该「已拉过一次」的标记复位,下一次掉线才允许再拉一次。

## 8. 测试与验证

**Python 侧(进现有 pytest 套件):**

- `supervisor`:一探即通 / 先死后活 / 超时 / 派生失败 / **派生环境中 `GUANLAN_PORT` 确已剔除** / 只派生看门狗,从不出现杀进程的调用
- `bridge`:`/ui/` 路径放行;`file://`、外部主机、其他端口、非 `/ui/` 路径全部拒绝,且拒绝理由带类型
- 启动形态守卫:快捷方式生成器产出的命令行必须是 `-m` 形式

**JS 侧——诚实声明:仓库中没有前端测试设施。** 因此:

- 浏览器路径用**真浏览器**验证:在 9999 上打开选股页、Ctrl+点导航,确认仍是原地跳转(`GL_DESKTOP` 不存在 → 老行为)。这是真证据,不是替身。
- 桌面路径需要真窗口。可在实现后启动并截图取证(需一次桌面访问授权),否则由用户验证。

## 9. 已知限制

- **Windows-only。** pythonnet + WebView2 决定的。这套系统本来就是 Windows-only,不构成新约束。
- **单机。** 不可分发;见 §1 非目标。
- **顶栏改动会被十二个页面同时吃到,不是八个。** `MODULES` 只列了 8 个 tab,但 `cards/`、`chat/`、`factor/`、`graph/` 四个页面仍在加载同一份 `guanlan-nav.js`(2026-06-12 phase2 收敛"隐藏不删"——从 tab 条隐去,`<script>` 标签留着)。这是 `guanlan-nav.js` 的既有性质,不是本设计引入的;页面数越多,没做条件化的代价就越大,条件分支正是为此而设。
- **桌面路径无自动化测试。** 无窗口测试设施;缓解手段是把全部真实逻辑放进 `supervisor`/`bridge` 这两个可无头测试的模块,`shell.py` 只留接线。
