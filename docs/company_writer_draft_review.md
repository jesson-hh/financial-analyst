# 公司报告生成端的有界修订

公司模式继续保留全部经证据/PIT 校验的平台数据与 quote/fundamental 分析，
但不再把旧交易流水线的 bull/bear、技术交易、主力交易和 CRO 结论作为最终写作输入。
这些旧节点包含价格锚与交易方向，不能作为发行人证据。旧 investment_report 模式不变。

最终 writer 在首次返回合法 JSON 后，调用既有 report gate 进行只读预检：
章节、引用、数字、issuer/context 边界、真实缺口披露和合规规则没有放宽。
模型 risk 输入复用最终落盘路径的清洗器，通过 risk builder 的独立
`model_risk_input` 通道解析，不能进入可信来源或确定性检查扫描器。
拒绝的 context/unknown 引用和不闭合的反证会进入修订反馈。

准备阶段还未生成的 risk/report 状态不是本轮写作错误；仅排除三个精确的
风险基线空数组缺口，不排除真实缺源。最终不可变证据账本、冲突、风险闭合、
状态和 report gate 仍在正常 finalization 路径重新验收。

有错误时最多追加一次模型修订，不另加 JSON 重试。合计上限为三次 writer
`client.chat`：首次请求、最多一次 JSON 语法重试、最多一次语义修订。
这里不宣称整个 legacy job 的调用或 token 预算已有运行时强制。

修订必须减少已发现的问题且不能新增失败类别，否则保留原稿。
缺源、失败的模型调用、不支持的数字与不闭合的反证不能通过自动替换或
伪造 complete 消失。即使预检没有问题，也不表示事实语义已获人工确认。

同一私有报告目录保存 `CODE_ASOF.draft-review.json`，保留原稿、候选稿及两次
预检详情。最终报告 manifest 仅携带精简审计、实际 writer 调用数和该文件名；
token 用量未测量时明确记为 unknown。此文件不是新证据来源，不能用于给报告背书。

修订反馈按原错误行汇总，并提供已引用来源的有界字段导航。原始日期、符号、单位、
数组位置保持不变；跳过失败/未来子树时不重新编号。资格判定与最终 Gate 相同，
缺输入来源链的计算即使标记 complete 也不能作为可用结果展示。导航不是新证据，
不把公式常数、计算输入或旁边的相近数字转换成已证明输出。
反馈最多 24 个引用、每引用 16 字段/3000 字符、引用合计 24000 字符，截断显形。

新 final 工作空间资产同时保存 `review_notes.md`：确定性展示 Gate 状态、错误码、
行号与有界原文摘录。它是非证据诊断附件，不修改完整性或新鲜度；完整 JSON 仍是
审计依据，风险结构通过仍不表示反证方向及引用蕴含关系已经独立语义核验。

情景假设的预检与保存使用同一个选择函数：非 null 的顶层 `assumptions` 优先
（显式空数组也优先），否则读取 `summary_json.assumptions`，过滤旧交易字段后
写回 sidecar 的 `assumptions`。最终 Gate 只能在验证该 sidecar 的完整性后使用
这个情景登记，不能把它提升为发行人证据或确定性计算。
